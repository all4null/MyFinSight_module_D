MyFinSight 프로토타입 · 묶음 D (결과·통합)

데이터가 어느 코드에서 어떻게 바뀌어 Report가 되는가

고정 Profile·Spec 파일에서 시작해 텍스트 Report가 저장될 때까지, 13개 단계에서 오가는 데이터와 그 데이터를 만드는 코드·수식을 정리했습니다. 파란색은 묶음 D가 구현한 부분, 회색은 다른 묶음(A·B·C)이 구현할 부분입니다. 예시 숫자는 저장소 테스트 시나리오(tests/conftest.py, 부록 A 예시 Profile·Spec)의 실제 결과입니다.

1. 전체 흐름2. 단계별 입출력3. 실행 기록 4. 근거 생성5. Report 조립6. 표시 규칙 7. 일치성 검사8. 오류·종료 코드9. 지표 수식10. 설명용 요약

1. 전체 흐름 runtime/pipeline.py

CLI(python -m myfinsight run)가 Pipeline.run()을 부르면, 파이프라인은 정해진 순서로 각 모듈을 호출하고 결과를 다음 단계에 넘깁니다. 파이프라인 자체는 계산하지 않고 호출 순서와 오류 처리만 맡습니다. 화살표 위 글자가 다음 단계로 넘어가는 데이터(M00-02 스키마)입니다.

3. 실행 기록 M08-01 runtime/runlog.py

각 단계는 with run_log.step("이름") as h:로 감쌉니다. 들어갈 때 STARTED를 저장하고, 끝날 때 결과에 따라 상태를 덮어씁니다. 같은 (run_id, step) 키에 저장하므로 단계마다 최종 상태 한 줄이 남습니다.

stateDiagram-v2
  [*] --> STARTED: step() 진입
  STARTED --> SUCCESS: 정상 종료
  STARTED --> PARTIAL: 정상 종료 + h.mark_partial(사유)
  STARTED --> FAILED: 예외 발생 (code·message 기록 후 예외 다시 던짐)
  [*] --> SKIPPED: run_log.skip() 고정 Universe일 때 constituents

기록되는 값 (StepRecord)

  • started_at, ended_at: UTC 시각
  • summary: h.set_summary() 문장
  • sources: h.add_source() 출처 (중복 제거)
  • error_code: MyFinSightError.code, 그 외 예외는 UNEXPECTED_ERROR

Report 12번 섹션 한 줄

라벨: 상태 (요약) [출처: …] 예) 데이터 품질 판정: 부분 성공 (20/21; 1개 제외) 예) Backtest: 실패 (BACKTEST_NO_PRICE: 가격 없음)

저장소 저장이 실패해도 경고 로그만 남기고 분석은 계속합니다.

9. Report 숫자의 원래 수식 묶음 B·C 참고

D는 아래 값을 계산하지 않고 받아서 표시·대조만 합니다. 발표 때 숫자가 어디서 왔는지 물으면 이 수식을 근거로 설명할 수 있습니다 (명세 M03-01·02, M05-01·02).

선정·비중 (B)
